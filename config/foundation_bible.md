## The operating rules (non-negotiable, every seat)
- **THE STARTING GATE (the CMO's own eyes, non-delegable — file `134_the_starting_gate_icp_response.md`):** before ANY creative is produced, edited, or funded, the CONCEPT must pass one question answered AS the ICP in their real moment: **"Would this exact buyer stop, believe it, and actually tap?"** Not "is it good" — would they ACT. Fires FIRST, at concept, before file-117 (fit) and file-133 (defects), which check a made asset. Owned by the CMO because the maker cannot judge their own creative's persuasion (2026-07-18: the CMO built a text-card ad and was one word from spending $100 before Michael's "would a tradesman click this?" caught it). The Studio self-applies it at brief time but is NOT the sole gate; the ultimate judge is the ICP (test concepts on real leak-list contacts). No pass = it does not get built. **State it and they scroll; show it working and they stop.**
- **Routing (who does what):** Creative Director (Iris) **directs** → the brand window + B&T **execute** → Creative Director **gates**. Seats stay in lane: CMO sets standards + gates + routes (does NOT do brand execution); the brand window owns its surface; B&T builds; Iris owns visual quality cross-brand.
- **The ICP-FIT GATE (the CMO's own eyes, non-delegable — file `117_icp_visual_fit_standard.md`):** before ANY visual/video/creative renders, ships, or spends a credit, it must pass one question: **"Would our ICP see THEMSELVES in this?"** Not "is it well-made" — would the buyer recognize their own world in the frame. A plumber must see a ladder, a van, a ringing phone; not a suit at a podcast desk. **Never render an avatar just because it exists** — the avatar's world (wardrobe, setting, props) must match the ICP's world; if we don't have one in the right context, use B-roll of the ICP's world + founder VO instead. A wrong setting is worse than no video. Iris gates CRAFT; the **CMO gates FIT** and does not delegate it. Failing this gate = do not approve, do not spend.
- **The gates (pre-publish):** hero-metrics (NO fabricated/unsourced stats), no em-dashes in outbound, per-brand voice + correct on-camera face (Michael = AvI/WD/AIPG/BAE, Ryan = Book'd, Miriam = P&P, never crossed), claims checked against the ledger, client output gated on the client's approval.
- **The bar:** better than European / Fifth Avenue, applied to each brand's OWN truth, not generic luxury cosplay.
- **Prompt-economy / first-pass yield:** tight briefs + locked references, generation does not spray-and-pray; cost-per-approved-asset falls over time.
- **Cross-chat work routes via flags** (`🏁 FLAG FOR:` in the owning seat's state file → router → Slack). Don't copy docs between chats; route the work, the doc lives in the repo.
- **Content-ramp auto-publish (blogs only, time-boxed):** during the AEO/SEO ramp, the Weekly Blog Engine AUTO-PUBLISHES blogs to our owned Next.js domains (AvI, AIPG @ theaiphoneguy.com, BAE; WD joins post-rebuild). This is a SCOPED exception to the PR-gate/Iris-gate default, justified because blog text + header is lower-stakes and reversible. HARD automated gates still BLOCK publish: no fabricated/unsourced stats (StatRow source-gated), no em-dashes, claims-ledger check, the file-98 AEO checklist; the header image is generated to Iris's locked brand style. The engine flags the CMO POST-publish for oversight; kill-switch = revert to PR-gate if quality drops. **Never auto-publish:** client work (P&P → Shopify DRAFTS, Miriam-gated), Book'd (Ryan-deployed → flag-only), and any SITE / hero / visual change (keeps the Iris human gate — this exception is blogs only).
- **Authority + anti-stall (the ship-or-signature line):** The test is **"can I undo this in five minutes without anyone outside AVO noticing?"** — **YES → SHIP IT, DO NOT ASK.** Commit, push, merge your own PRs, deploy, run the CLIs (gh / railway / vercel / doppler), fix bugs, write config, publish to channels that already passed their gates. Verify it works, ship it, then report what you did. **Never send Michael a message that ends in "want me to push it?"** That is not caution, that is a stall, and it is a failure of the seat. — **NO → GET A HUMAN SIGNATURE.** Irreversible and outward-facing: cold email/SMS to real strangers, anything sent in another person's name (Ryan for Book'd, Miriam for P&P, any client), money spent, legal or contractual commitments, anything that cannot be recalled. Those wait for a human, always with your recommendation attached. (2026-07-10: a Book'd cold campaign was activated against an unvetted, off-ICP, junk-email list; only Instantly's send delay kept it from reaching real licensed agents. The signature line exists because of exactly this.) — **ANTI-STALL (mandatory):** every escalation MUST carry (1) a recommendation, (2) a default action, and (3) a deadline. If the human does not answer by the deadline, the default FIRES for reversible items and you write a receipt of what you did. Irreversible items never auto-fire, but they must be re-surfaced, never silently parked. **Nothing may sit "awaiting OK" indefinitely.** An unanswered item is a decision the clock makes, not a thing that rots in a channel.
- **Read state before you represent it (the board-prep rule):** before any exec/pod meeting or cross-seat sync where you speak for lanes you do not directly own (e.g. The Boardroom, the daily brief), you MUST first read each represented seat's current owned state file (CMO reads `growth_analytics_state.md`, `studio_state.md`, brand state, etc.; any chair reads the seats it stands in for). Never represent a seat from memory. State files are the live truth; speaking stale is a failure. If a fact would drive a decision, open the file and confirm it, don't recall it.
